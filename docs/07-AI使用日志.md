# AI 使用日志

## 说明

- 使用工具：Claude 桌面版（模型 `claude-haiku-4-5`），会话内直接读写项目文件、启动 MongoDB、执行 pytest。
- 记录方式：按"一次有效交互"记一条，包含提示词、得到的产出、是否修改、改了什么。
- 原则：失败与返工也记录，"AI 一次写对"不是真实情况，也不是这门课想看到的东西。

## 5.1 AI 使用日志

### 记录 1 · 需求拆解与技术选型

**提示词（摘要）**

> 这是《当代数据管理系统》大作业一第一阶段的文档。我要做完整项目：代码、schema、测试、文档。
> 后端语言和框架你帮我选，要求能在本机跑起来、能真机验证。

**结果**：给出 Flask + pymongo 的选型理由（无构建步骤、聚合管道直接用、课程演示够轻），
以及"四个集合 + 纯函数逻辑层"的初步架构。

**是否修改**：是。
**修改内容**：把"问卷和题目合并成一个文档"改成两个集合。理由是题目要单独编辑、要被跳转引用，
合并后每次改题都要重写整个数组，且热门问卷文档会持续膨胀。

### 记录 2 · 数据库 schema 设计

**提示词（摘要）**

> 设计 MongoDB schema：用户、问卷、题目（单选/多选/文本/数字）、回答。
> 要求说明为什么这样设计、为什么不用关系型、为什么适合 MongoDB。
> 注意题目有校验规则和跳转规则，跳转不能写死在代码里。

**结果**：给出 `users / surveys / questions / responses` 四个集合的字段草案，
题目里用 `rules` 和 `logic` 两个自由对象承载校验与跳转，回答把答案嵌在文档内。

**是否修改**：是。
**修改内容**：
1. 给 `responses` 增加 `path` 字段，记录实际走过的题目顺序——AI 初稿只存了答案，
   但"展示过但没答"的题在统计作答率和分析跳转时需要，`answers` 里没有这个信息。
2. 增加 `survey_version`，为第二阶段的需求变更留兼容位。
3. 明确 `slug` 与 `_id` 并存：外链用短码，不暴露内部主键。
4. 补充多键索引 `survey_id + answers.question_id`，否则统计单题会退化成全表扫描。

### 记录 3 · 校验与跳转引擎

**提示词（摘要）**

> 写一个纯函数模块，负责单题校验和跳转计算，不依赖 Flask 和 pymongo。
> 要能处理：单选按选项跳、多选按包含关系跳、数字按比较/区间跳；
> 提交时要能发现"给被跳过的题提交答案"这种作弊；还要防止规则成环。

**结果**：生成 `app/logic.py`，包含 `validate_answer`、`match_condition`、`resolve_target`、
`build_path`、`next_question`，以及 `PathResult` 数据结构。

**是否修改**：是。
**修改内容**：
1. 数字校验补充 `bool` 排除与 `math.isfinite` 判断（`True` 在 Python 里是 `int`，不排除会被当成 1）。
2. `build_path` 增加"未知题目 id"检查，原先只检查"被跳过的题"，漏了构造不存在 id 的情况。
3. 环路检测从"只看步数上限"改为"visited 集合 + 步数上限"双保险，报错信息也更具体。

### 记录 4 · 数据库层校验器与建库脚本

**提示词（摘要）**

> 用 $jsonSchema 给四个集合加校验器，写一个可重复执行的建库脚本，支持 --drop 和 --show。
> 索引列出来，说明每个索引服务哪个查询。

**结果**：`app/db.py` 的 `COLLECTIONS` / `INDEXES` 定义与 `schema/init_db.py`。
校验器覆盖 enum（状态、题型）、必填字段、字符串长度。

**是否修改**：是。
**修改内容**：把 `rules` / `logic` 的校验器从"逐字段枚举"改成"只要求是 object"。
原因：第二阶段要加新校验项，如果校验器锁死字段，加字段就得先改库，违背"结构可扩展"的初衷。
业务级规则本来就在 `logic.py` 里，数据库层只需要守住形状。

### 记录 8 · 修复：多选跳转不生效

**提示词**

> 多选跳转的测试失败了，期望跳到第 3 题，实际到了第 2 题。查一下原因并修。

**结果**：定位到 `_build_logic` 对所有选择题都生成 `{"option": key}`，
而 `match_condition` 对多选题只认 `contains_any / contains_all / count`，所以永不命中。

**是否修改**：是。
**修改内容**：多选题改为生成 `{"contains_any": [key]}`；补一条"只选 C 不命中"的对照用例，
确认不是"所有情况都跳"。

### 记录 10 · 修复：全量测试时 MongoDB 崩溃

**提示词**

> 单独跑每个测试文件都通过，一次跑全部时第 80 个左右开始报 ServerSelectionTimeoutError。
> mongod 日志里有 Too many open files。帮我定位。

**结果**：每个用例 `drop_database` + 重建带校验器的集合，反复建删导致 WiredTiger 文件句柄耗尽，
而环境 `ulimit -n` 只有 1024。

**是否修改**：是。
**修改内容**：改成会话级建库一次、用例级只清空文档；测试时间从 100 多秒降到 30 秒，
105 个用例全部通过。同时保留 `ulimit` 提示给运行脚本。

## 5.2 AI 使用说明

### AI 帮了什么

- 按需求快速铺出四个集合的字段草案与索引清单，省掉了查文档的时间；
- 生成校验/跳转引擎、Flask 路由、模板、样式、测试骨架；
- 把"跳转要能表达为数据"落到具体的 JSON 结构，并给出匹配函数的实现；
- 写文档初稿，尤其是把设计取舍整理成可读的段落。

### AI 做错了什么

| 问题 | 表现 | 为什么危险 |
| --- | --- | --- |
| 多选跳转条件用错 | 生成 `option` 条件，多选题永不命中 | 界面配置成功、实际不跳，属于"静默错误" |
| 模板 dict 点号访问 | `data.values` 取到内置方法，页面 500 | 测试只断言状态码就会漏掉 |
| 测试数据库反复建删 | 全量跑时 MongoDB 文件句柄耗尽崩溃 | 单文件测试全绿，掩盖了问题 |
| 测试漏登录 | 注册后直接建卷，被重定向 | 测试"通过"了但实际什么都没建 |
| 初稿回答只存 `answers` | 缺少 `path`，无法统计作答率 | 属于数据模型层面的信息缺失 |
| 合并单元格丢提示文字 | 提示写在 C 列后合并 A:G，只剩左上角 | 导出文件少一行提示，只有断言内容才发现 |

共同点：都不是语法错误，而是**设计判断与验证深度**的问题。语法错误编译器会拦，
这类错误只有跑起来、断言具体数值、看日志才会暴露。

### 自己改了什么

- 复核字段与需求的对应关系：确认"匿名"只表示不记录身份，不表示不用登录；
  确认多选题的三种数量限制（最少/最多/必须）都能独立配置；
- 确定跳转语义为"从上到下第一条命中即跳"，并在文档里写死，避免歧义；
- 把"提交时从头重算路径"定为硬性要求，而不是信任前端传来的答案集合；
- 调整统计分母为"回答过本题的人数"，而不是总提交数；
- 增加删除题目时清理悬空跳转；
- 修正 AI 的四处实现错误（见上表），并为每个错误补了能复现的测试。

### 自己设计了什么

- **集合划分的边界**：问卷/题目用引用，回答/答案用嵌入——这条边界决定了后续所有查询与写入方式；
- **`responses.path`**：把"展示过哪些题"和"答了哪些题"分开存；
- **服务端驱动的填写流程**：每答一题由服务端算下一题，客户端拿不到完整跳转权；
- **两层校验的职责划分**：数据库校验器管形状，`logic.py` 管业务规则；
- **第二阶段的兼容位**：`survey_version`、自由对象的 `rules/logic`、按 `question_id` 聚合的统计口径。
