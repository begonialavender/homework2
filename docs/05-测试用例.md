# 测试用例

## 1. 测试环境

| 项 | 值 |
| --- | --- |
| 操作系统 | Linux（Ubuntu 22.04 运行环境，与 Windows 行为一致的部分已在 Windows 上手工验证） |
| MongoDB | 7.0.14，单机，`127.0.0.1:27017`，测试库 `survey_system_test` |
| Python | 3.10.12 |
| Flask / pymongo / pytest | 3.1.3 / 4.18.3 / 9.1.1 |
| 执行命令 | `pytest -q` |

**执行结果：`122 passed`（约 15 秒）**，无失败、无跳过。测试库每个用例前清空，不会污染业务数据。

测试分三层：

- `tests/test_logic.py`：纯函数单测，不连数据库，覆盖校验与跳转的全部边界；
- `tests/test_auth.py`、`test_survey_manage.py`、`test_fill_jump.py`、`test_validation.py`、`test_stats.py`、`test_export.py`：走真实 HTTP 路由 + 真实 MongoDB；
- `tests/test_schema.py`：直接对数据库写非法文档，验证 `$jsonSchema` 与唯一索引确实生效。
- 导出的 xlsx 用 openpyxl 重新打开断言内容，而不是只检查 HTTP 200。

## 3. 手工验收步骤（演示用）

1. 启动 MongoDB 与 `python run.py`，打开 `http://127.0.0.1:5000`。
2. 注册 `alice`，创建问卷，添加：
   - 单选"你平时运动吗？"（经常 / 偶尔 / 从不），必答，配置"经常 → 跳到第 4 题"；
   - 文本"每周几次？"；
   - 数字"年龄"（0~120，整数）；
   - 文本"有什么建议？"。
3. 发布，复制链接，在另一个浏览器（或无痕窗口）注册 `bob` 并打开链接。
4. 选"经常"，确认直接跳到第 4 题；输入建议并提交。
5. 换回 `alice`，打开统计，确认第 1 题为 1 人选择"经常"，第 2 题为 0 人回答。
6. 直接构造 POST 请求，给被跳过的第 2 题塞答案，确认返回 400 且回答数不增加。
7. 在统计页点「导出 Excel」，用 Excel 打开：应有「问卷信息」「统计汇总」两张表，占比列显示为百分比且仍是数字。

## 4. 覆盖情况说明

- 课程要求的六类必测项（创建问卷、添加题目、跳转逻辑、校验、提交问卷、统计）全部有自动化用例，并在上表逐条对应。
- 未覆盖的部分：浏览器端 JS 的交互细节（下拉切换、进度条动画）只做了人工点击验证，没有做自动化 UI 测试；
  当前阶段没有引入 Selenium/Playwright，理由是本项目的风险集中在服务端规则，前端只是渲染与转发。
- 并发提交没有写压力测试，但写入模型是单文档 `insertOne`，不涉及共享状态；
  问卷级并发编辑（两个人同时改同一题）没有加乐观锁，属于已知限制。
