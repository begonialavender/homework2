# 关键逻辑说明

本项目的复杂度集中在三个地方：**单题校验**、**跳转计算**、**提交时的路径重算**。
三者都实现在 `app/logic.py` 里，全部是纯函数（输入题目列表和答案字典，输出结果或错误），
不依赖 Flask 与 MongoDB。这样写不是为了"好看"，而是因为跳转逻辑一旦和框架耦合，就没法单独测。

## 1. 单题校验

入口：`validate_answer(question, raw) -> 规范化后的值`，不合法时抛 `ValidationError`。

| 题型 | 规则 | 规范化 |
| --- | --- | --- |
| 单选 | 值必须是选项 key 之一 | 原样返回 key |
| 多选 | 必须是 key 数组；不允许重复、不允许未知 key；按 `exact_choices` / `min_choices` / `max_choices` 检查数量 | 返回去重后的列表 |
| 文本 | 必须是字符串；按 `min_length` / `max_length` 检查字符数（Python `len`，中文按字算） | 原样返回 |
| 数字 | 允许数值或数字字符串；`integer` 时必须是整数（"18.5" 直接拒绝，不做隐式取整）；按 `min_value` / `max_value` 检查 | 整数转 `int`，否则 `float` |

空值先统一判断：

```python
if is_empty(raw):              # None / "" / [] 都算空
    if question["required"]:
        raise ValidationError("本题为必答题")
    return None                # 选答题留空 → None，不写进 answers
```

两个容易踩的点，这里明确处理了：

- **`True` 不是数字 1**。Python 里 `isinstance(True, int)` 为真，所以数字题先排除 `bool`，否则"是否整数"的勾选值会变成 1。
- **`NaN` / `Infinity`** 会被 `math.isfinite` 拦下，避免统计时平均值变成 `NaN`。

## 2. 跳转条件

一条跳转规则就是一个字典：

```javascript
{ when: { ...条件... }, target: "题目 id" | "end" }
```

按题型支持的条件：

| 题型 | 条件写法 | 含义 |
| --- | --- | --- |
| 单选 | `{"option": "A"}` | 选了 A |
| 多选 | `{"contains_any": ["A","B"]}` | 选中任意一项 |
| 多选 | `{"contains_all": ["A","B"]}` | 同时选中 A 和 B |
| 多选 | `{"count": {"op":"gte","value":2}}` | 选中数量满足比较 |
| 数字 | `{"op":"gte","value":60}` | 数值比较（eq/neq/gt/gte/lt/lte） |
| 数字 | `{"op":"between","value":18,"value2":30}` | 闭区间 |
| 文本 | `{"equals": "其他"}` | 内容完全相等（第一阶段的可选能力） |

匹配在 `match_condition` 里一次性实现，界面上的"条件"下拉框只是这个字典的另一种写法。

`resolve_target` 的顺序是：**从上到下遍历 `jumps`，第一条命中的就用它**；都没命中时看 `default_next`
（`next` 继续下一题，`end` 结束）。

## 3. 下一题与路径重算

这两个函数是整套跳转的核心，职责不同但共用同一套规则：

### 3.1 `next_question(questions, answers)`

填写过程中调用。从第一题开始走：

```
对路径上的每一题：
    如果这题还没作答 → 停下，返回这题（让前端渲染）
    如果作答了 → 校验；按规则算出下一题；继续
走到 end → 返回 (None, [], finished=True)
```

它**不会**因为后面还有必答题未答而报错——那正是还没问到的题。

### 3.2 `build_path(questions, answers)`

提交时调用。与上者的区别是：**走完整条路径，并且对每条答案严格校验**。

```
路径 = []
visited = {}
current = 第一题
while current 存在且不是 end:
    if current 已访问 → 报错"跳转规则形成环路"
    校验这道题的答案（缺必答 → 报错）
    记录 path 和 value
    current = resolve_target(...)
走完后，检查用户提交的每个 question_id：
    不在题目列表 → "题目不存在或不属于本问卷"
    不在 path 里   → "该题已被跳转规则跳过，不应提交答案"
```

最后一步是防作弊的关键。举例：Q1 选 A 直接跳到 Q4，有人手动提交了 Q2 的答案，
`answers` 里多出来的 Q2 不在 `path` 中，整次提交被拒绝。没有这一步，统计里就会出现"没被问过却答了"的数据。

### 3.3 环路与悬空目标

跳转规则是用户配的，配错很正常，所以两种坏数据都要挡：

- **环路**：`visited` 集合 + 步数上限，命中即返回"跳转规则形成环路，无法继续"，不会死循环。
- **悬空目标**：目标题目被删除后，`resolve_target` 返回一个不存在的 id，
  `build_path` / `next_question` 检查 `by_id` 后报"跳转目标题目不存在"。
  删除题目时也会主动清理其他题目里指向它的规则，双保险。

## 4. 填写页的交互顺序

前端每答一题就请求 `/answer`，服务端返回下一题；最终 `/submit` 再整体重算一遍。
为什么不在前端算跳转、最后一次性提交？

- 前端拿到全部规则，就等于把"哪题该出现"的判断交给了客户端，改一下 JS 就能跳过必答；
- 服务端逐步推进，还能在每一步即时校验（比如多选超限），错误提示更准；
- 提交时重算是最后一道闸门，即使前两步被绕过，也不会写入脏回答。

代价是每答一题多一次请求。对课程项目的量级完全可以接受，换来的是逻辑只有一份。

## 5. 统计的聚合实现

单选的管道：

```javascript
[
  { $match: { survey_id: ObjectId(...) } },
  { $unwind: "$answers" },
  { $match: { "answers.question_id": "<qid>" } },
  { $group: { _id: "$answers.value", count: { $sum: 1 } } }
]
```

多选在此基础上再 `$unwind` 一次 `answers.value`（因为值是数组），然后分组。

数字题用 `$group` 同时算 `$avg / $min / $max / $sum`，一次扫描拿到全部指标。
文本题直接投影出值，按提交时间倒序展示。

百分比的分母是**回答过本题的人数**（`count_documents({survey_id, "answers.question_id": qid})`），
不是总提交数。这样跳转导致的"没被问过"不会被算成"弃答"。
多选题的百分比因此可以超过 100%，界面上已注明。

## 6. 一份回答的写入

```python
doc = {
    "survey_id": survey["_id"],
    "respondent_id": None if anonymous else user["_id"],
    "anonymous": anonymous,
    "submitted_at": now(),
    "survey_version": 1,
    "path": result.path,          # 实际走过的题目 id
    "answers": result.answer_docs()  # 只含有值的题
}
db.responses.insert_one(doc)
```

一次 `insertOne` 完成全部写入，不依赖事务，也不会出现"答案写了一半"的状态。
`path` 与 `answers` 分开存的原因见数据库设计文档第 7 节。

## 7. 边界情况清单

| 情况 | 行为 |
| --- | --- |
| 问卷是草稿 | 填写页 403，提示未发布 |
| 已过截止时间 | 403，提示已过截止时间（不改变状态） |
| 问卷已关闭 | 403，已有回答和统计保留 |
| 同一人已提交且不允许重复 | 填写页直接提示；接口返回 409 |
| 匿名问卷 | 不记录 `respondent_id`，因此无法限次，允许多次 |
| 题目被删除后仍有旧回答 | 统计按题目回查，孤儿答案不展示；不影响其他题 |
| 提交时多带了被跳过的题 | 400，整次提交拒绝 |
| 跳转指向自己 / 形成环 | 保存时忽略自指；运行时检测环路并报错 |
| 空问卷被发布 | 拒绝，提示至少一题 |
